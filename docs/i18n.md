# Idiomas en Moka

Moka utiliza `i18next` y `react-i18next`. El idioma cambia inmediatamente: no se recarga la aplicación, no se modifican las rutas ni se reinicia el estado de los formularios. La preferencia sigue guardándose en `moka_language`.

## Dónde agregar textos

Los catálogos están en `src/i18n/locales/<idioma>/<namespace>.json`:

| Namespace | Contenido |
| --- | --- |
| `common` | Acciones compartidas, navegación, paginación, accesibilidad y errores generales. |
| `auth` | Inicio de sesión y registro. |
| `placements` | Tipos, estados, visibilidad, formularios y detalles de espacios. |
| `inventory` | Acciones, búsquedas, mapa y mensajes específicos del inventario. |
| `reviewHub` | Asignaciones, decisiones, historial y errores `REVIEW_*`. |
| `settings` | Cuenta, perfil y apariencia. |
| `validation` | Reglas y mensajes de validación de campos. |

Usa claves descriptivas en camelCase y los mismos nombres en todos los idiomas. Los identificadores técnicos (`UNIPOLE_BILLBOARD`, `REVIEW_STALE`, etc.) conservan sus nombres.

```jsx
import { useTranslation } from 'react-i18next';

function ClaimButton() {
  const { t } = useTranslation('reviewHub');
  return <button>{t('claim')}</button>;
}
```

Para otra sección: `t('common:actions.cancel')`. Los componentes deben suscribirse mediante `useTranslation`; no guardes traducciones en un estado o en constantes de módulo. Guarda estados, errores o claves y tradúcelos al renderizar, para que también cambien los mensajes que ya están visibles. Los servicios devuelven códigos/datos; `translateError` y `fieldError` convierten errores en mensajes de interfaz.

## Frases y cantidades

Traduce frases completas; evita construirlas concatenando palabras. Usa variables para datos que cambian y plurales para cantidades:

```json
{
  "availableFaces_one": "{{count}} cara disponible",
  "availableFaces_other": "{{count}} caras disponibles"
}
```

```jsx
t('placements:availableFaces', { count: faces.length })
```

Agrega las formas plurales que necesite cada idioma. La comprobación usa las reglas de `Intl.PluralRules` para exigir las formas que necesita cada idioma. En español también se incluye `_many` para cantidades como un millón.

Los nombres de personas, descripciones, direcciones y motivos escritos por usuarios conservan su contenido original. Tampoco se traducen los códigos usados por la API, rutas, IDs ni valores de enums.

## Idioma y formatos

- `languages.js` define los idiomas admitidos, el idioma de respaldo (`es`) y los formatos regionales (`es-MX`, `en-US`).
- Se restaura la preferencia guardada; si no existe, se consulta el navegador. Un idioma no admitido usa español.
- `changeLanguage` valida la selección. `index.js` sincroniza `html.lang`, la dirección de escritura y el almacenamiento; funciona también si localStorage está bloqueado.
- `LanguageProvider` aplica el formato regional a los controles de React Aria/HeroUI.
- `formatters.js` contiene los formatos de precios y fechas. El idioma de presentación y la moneda son independientes: cambiar a inglés conserva los precios en MXN y no convierte importes.
- La consulta geográfica del formulario conserva `es-MX` para mantener consistentes los nombres de lugares guardados y sus filtros. Ese contenido pertenece a los datos del espacio.

Las rutas actuales siguen siendo compartibles. Una futura estrategia de SEO con `/es/` y `/en/` requeriría planear rutas, enlaces canónicos y `hreflang`; no forma parte de cambiar el idioma de la interfaz.

## Agregar un idioma

1. Crea una carpeta con los siete catálogos y traduce su contenido.
2. Registra el idioma y su formato regional en `languages.js`.
3. Importa sus JSON y agrega sus recursos en `resources.js`. El selector toma las opciones de `AVAILABLE_LANGUAGES`.
4. Ejecuta las comprobaciones y revisa las pantallas, diálogos y validaciones en el nuevo idioma.

Los catálogos se incluyen en el build: no requieren una base de datos, un servidor de traducciones ni peticiones extra al cambiar de idioma. Los namespaces permiten incorporar carga diferida si el volumen de textos lo justifica más adelante.

## Verificación

```bash
pnpm check:i18n
pnpm test
pnpm lint
pnpm build
```

`build` ejecuta la comprobación de catálogos antes de compilar. `check:i18n` detecta claves faltantes, variables inconsistentes, referencias estáticas desconocidas y usos del sistema anterior. Las pruebas cubren respaldo a español, detección y persistencia, plurales, errores y formatos regionales. Revisa también las claves dinámicas de tipos, estados y pestañas cuando agregues nuevos valores.
